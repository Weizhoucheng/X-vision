# 架构与线程模型

X Vision 将生产检测操作与 VM SDK 调用分层，目标是统一图像输入、检测状态和结果流转，便于维护 GUI 及独立 SDK 两种使用方式。

| 项目 | 职责 |
| --- | --- |
| VisionInspect.Core | 图像/结果/配置模型，接口，检测状态机，结果判定，统计 |
| VisionInspect.Infrastructure | 配置读写，本地图像，认证，异步归档，CSV/XLSX，结果管道 |
| VisionInspect.VisionMaster | 官方 SDK 调用，流程与模块输出，参数适配，STA 调度及运行环境定位 |
| VisionInspect.Cameras | MVS 设备访问、采集、触发、参数写入和预览节流 |
| VisionInspect.Communication | Modbus TCP、TCP 触发/发送、串口 IO 与各通道生命周期 |
| VisionInspect.App | WinForms 窗体、VM 控件宿主、用户操作与运行服务组合 |
| XVision.Sdk | 独立于 GUI 的方案加载、图像检测、参数访问、保存及释放接口 |

## 一次检测

输入提供器生成 `RawImage`，检测控制器串行执行方案，判定服务生成 OK/NG，结果管道更新统计、记录日志、排队归档并输出通讯结果。停止和取消围绕当前检测与结果处理边界协调，避免重复运行与释放竞争。

## 线程约束

UI 线程负责控件及界面事件；VM 适配器以独立 STA 线程和消息泵访问引擎对象。MVS 回调拷贝图像及发布预览，预览节流与算法检测取图分离。通讯连接和归档在后台工作，归档队列同时限制数量和内存；满队列有日志记录。

## 即时配置

先停止并等待当前检测及结果处理结束，暂存新存储服务与配置，将新值应用到保持稳定引用的配置对象，按差异重建通讯通道，再保存配置并发布新服务。设备写入或配置保存失败时报告错误，尝试恢复旧通讯与相机参数；保存成功后才执行新的归档保留期清理。修改数据路径不会搬迁历史文件。

## 主题与原生控件

主题采用配色过渡并保留 VM 渲染控件。十字线和大结果由透明覆盖层绘制。覆盖层使用颜色透明键，必须跳过普通窗体背景着色并保留透明键颜色；回归同时检查控件句柄和覆盖层背景像素。

## SDK 边界

`XVisionClient` 使用信号量串行化方案、运行及释放请求；调用者路径相对显式基目录解析。封装不启动主窗体、相机或通讯，也不改变海康授权条件。
