# `.sol` 方案制作约定

本项目不内置真实项目方案。请先在 VisionMaster 客户端中制作并验证方案，再放入本程序加载。

`samples/images/demo-part.png` 只是一个用于本地图片链路的合成演示图，不是生产样件；可直接在“本地图像”中导入验证渲染/日志/归档。

## 1. 推荐流程结构

```text
流程：Flow1（名称可自定义，建议全英文/数字）
  ├─ 图像源：ImageSource1（SDK 模式由程序设置）
  ├─ 定位 / 测量 / 识别 / 检测模块...
  ├─ 格式化：Format1（可选，用于拼装显示/判定字符串）
  └─ 输出图像 / 结果

流程输出（Output）：
  ├─ 检测结果（String，值 "OK" 或 "NG"）
  ├─ 可选测量值（Float/Int/String）
  └─ 可选图像输出
```

### 关键要求

1. **图像源由上位机注入**：程序会把图像源切为 SDK 模式并调用 `SetImageData`。在 VM 中不要配置相机或本地图片自动播放作为生产输入；相机采集由 MVS 适配层负责。
2. **主流程只运行一次**：不要让流程内部配置连续运行/循环；循环由本程序的 `DetectionController` 控制。
3. **流程输出必须包含判定结果**：最稳妥的做法是在流程“输出设置”中增加一个 String 输出，例如 `检测结果 = "OK"/"NG"`，并配置到本程序 `ResultJudge.JudgeOutputName`。
4. **格式化模块负责展示值**：格式化输出会额外读取并显示，但判定优先使用流程输出。
5. **不要在流程中依赖人工确认/弹窗**：无人值守会卡死检测。
6. **模块名尽量稳定**：参数预设按 `<流程名>.<模块名>` 保存；改名会导致预设/默认值失效。
7. **图像格式**：Mono8 / RGB24（BGR 会由程序转换）。不建议在流程中假设 Bayer 输入。

## 2. 在 VM 客户端制作步骤

1. 新建方案，保存为 `D:\VisionRecipes\产品型号.sol`。
2. 新建流程，命名 `Flow1`。
3. 拖入“图像源”，命名 `ImageSource1`。
4. 拖入定位/测量/检测模块并完成标定、ROI、阈值。
5. 拖入“格式化”模块（如需要），将结果拼成字符串。
6. 配置流程“输出设置”：
   - 添加 `检测结果`（String）。
   - 添加需要在界面/报表中显示的数值/字符串变量。
   - 如需渲染图像，添加图像输出。
7. 用 VM 的“本地图像”测试多张 OK/NG 图，确认输出名与值。程序默认把渲染源绑定到最后一个检测模块（可在“图像显示”下拉中切换流程整体/任意模块）；为了让图像和 ROI 正常显示，至少保留一个带图像输入的检测模块。
8. 保存 `.sol`。
9. 在本程序中以管理员登录 → 方案管理 → 添加 → 加载。
10. 用本地图片模式先验证（无需接相机），再做相机联调。

## 3. 格式化模块建议

格式化模块的 `format_out` 是字符串列表，程序会映射到模块输出叶子名称。

建议格式：

```text
结果: {检测结果}
X: {X:F3}
Y: {Y:F3}
Diameter: {Diameter:F3}
```

或者直接只输出：

```text
OK
```

但为了让判定稳定，建议流程输出 `检测结果` 使用独立 String 变量，不要仅靠格式化模块的 UI 展示。

## 4. 输出类型与显示

| VM 输出类型 | 程序显示 | 备注 |
|---|---|---|
| Int | 数值 | 名称命中布尔规则时按 True/False 显示 |
| Float | 数值 | 保留 9 位有效数字 |
| String | 字符串/布尔 | "True"/"False" 自动按布尔显示 |
| Image | `[图像输出]` | 不展开像素，避免结果表过大 |
| 点/线/圆/轮廓等复杂类型 | `[复杂类型]` | 如需展示请扩展 `ReadOutputValue` |

多值输出会以逗号拼接成一行。

## 5. 判定示例

### 方案 A：流程输出 `检测结果`

`ResultJudge`：

```json
{
  "JudgeOutputName": "检测结果",
  "OkKeyword": "OK",
  "NgKeyword": "NG",
  "UseFailSafeScan": true,
  "UseProcedureStatusAsFallback": true
}
```

流程输出：

```text
检测结果 = "OK"
```

### 方案 B：全部文本扫描

如果不配置 `JudgeOutputName`，程序扫描全部文本/布尔输出，任意包含 `NG` 关键字判 NG。该策略适合快速联调，但生产建议使用方案 A，避免某个中间字符串误触发。

### 方案 C：流程状态回退

如果方案没有显式结果字符串，可把 `UseProcedureStatusAsFallback=true`，程序使用 `Procedure.IsRunOK`。注意：这要求 VM 流程状态真实反映检测结论。

## 6. 参数与预设

- 参数预设使用 `ModuParams` 的简单属性；ROI/模板等复杂参数请在 VM 原生参数控件里维护。
- 默认值在首次加载方案时快照到：
  `<ConfigRoot>\params\defaults\<方案文件名>\<流程.模块>.json`
- 若修改了方案结构，删除旧默认值文件后重新加载，避免不匹配。

## 7. Modbus 映射

默认寄存器布局（`StartRegister` 起）：

| 偏移 | 内容 |
|---|---|
| 0 | 结果：OK 值 / NG 值（默认 1/2） |
| 1 | 检测序号低 16 位 |
| 2 | 耗时 ms |
| 3+ | 通过 `Mappings` 映射的输出，例如 `Diameter` → 偏移 3，Scale=1000（按整数传输） |

配置在 `appsettings.json`：

```json
"Mappings": [
  { "OutputName": "Diameter", "RegisterOffset": 3, "Scale": 1000.0, "Enabled": true }
]
```

实际 PLC 字节序/字序需按 PLC 手册核对。

## 8. 验收前自检

- [ ] VM 客户端单张图片可稳定输出 OK/NG。
- [ ] 流程输出名与程序配置一致。
- [ ] 方案内没有相机自动取流/循环触发。
- [ ] 图像源可被切换到 SDK 模式。
- [ ] 至少 1 个图像源模块存在。
- [ ] 格式化模块输出不包含会导致误判的 `NG` 字样。
- [ ] 相机触发模式与产线信号一致。
- [ ] 连续运行不依赖人工点击 VM 界面。
